# Phase 3: v1 adversarial audit and v2 remediation ledger

Status: audit conducted against the separately shipped `AVRL_v1_baseline.zip`. Each numbered entry describes a realistic defect class. **Mitigated** means a local safeguard was added; it does not imply a malicious process sharing the operator's account is contained. Some infrastructure requirements are external and therefore remain explicit deployment gates.

| ID | Dimension | v1 failure mode | v2 remediation and residual risk |
|---|---|---|---|
| H01 | Hook bypass | An allowlisted Bash command can still be abused through unexpected shell expansion or a newly exposed tool if matching is incomplete. | **Mitigated locally**: retained strict `tools: Bash` and strengthened PreToolUse positive whitelist for only `scripts/blind_browser.py` actions; test attacks. Sophisticated same-user process escapes still require OS sandbox. |
| H02 | Hook bypass | Unknown MCP/file tools and browser fetch tools bypass narrow named matcher. | **Mitigated locally**: wildcard matcher plus deny all blind agent tools except allowed browser helper; agent allowlist denies MCP. Managed settings/hook disable still out of scope. |
| H03 | Hook bypass | An older Claude Code client or a failing nonblocking Stop/TaskCompleted hook may not enforce the intended result. | **Partly mitigated**: retain `onFailure: block` for PreToolUse, require Claude Code >=2.1.295 and verify effective settings; Stop/TaskCompleted cannot be made fail-closed this way and require CI enforcement. |
| H04 | Hook bypass | Code could be written before eval approval through Edit/Write/Bash. | **Partly mitigated**: preapproval source guard allows only contract writes and narrow Git/CLI commands. Arbitrary interpreter processes and modified policy files require external FS protection. |
| H05 | Hook bypass | The actor can modify hook scripts, `.claude/settings.json`, state files or use `disableAllHooks`. | **External gate**: protected CI, immutable tools from trusted base, managed policy and separate OS identities. Hooks alone cannot solve this; never claim otherwise. |
| S01 | State synchronization | An agent crash/truncated write corrupts `state.md`. | **Mitigated**: canonical versioned JSON, atomic fsync+replace, lock, regenerated Markdown, bounded backup, validation. Operator must reconcile corrupt snapshots and re-run checks. |
| S02 | State synchronization | Changed eval scenario or mockup PNG preserves falsely approved eval.md. | **Mitigated**: fingerprint covers PRD, eval.md, eval.json, scenarios, decision log, all mockup assets; human signatures keyed to digest. |
| S03 | State synchronization | Agent forges `PASS` lines or reuses evidence from old SHA/feature. | **Mitigated**: deterministic runner, per-criterion SHA, eval hash and evidence checksum; final verification repeats checks and rejects missing/uncommitted results. Same-user agent can still tamper with runner; protected CI required. |
| S04 | State synchronization | Duplicate/high-risk approvals appear as one approval or sign-off covers changed code. | **Mitigated**: distinct interactive actors, 2-person high-risk eval and commit-bound release attestations, 1-person medium-risk release. CI platform branch protection still required for legally/operationally enforceable separation. |
| S05 | State synchronization | Crash mid-round leaves status ambiguous; concurrent agents overwrite state. | **Mitigated**: advisory `fcntl` lock, atomic updates and explicit pause/status. On recovery re-check Git and re-run stale checks; no automatic success from backup. |
| T01 | Context bloat | Full repeated review of unchanged files and logs exhausts context. | **Mitigated procedurally**: round 1 full changed-feature diff, later delta-only review + targeted regressions; store logs outside context; include bounded summaries, `maxTurns`. Need orchestration observability for very large repos. |
| T02 | Context bloat | Multi-agent unlimited rounds and same nit repeated indefinitely. | **Mitigated**: three-round architectural checkpoint, optional explicit human approval to continue through five, repeated same fingerprint after two fixes forces rethink, maxTurns. |
| D01 | Deadlock | A completion hook can trap human-approval questions or repeatedly block after an agent has already been instructed to continue. | **Regression-tested**: `awaiting-approval`, `paused`, `rethink`, `failed` allow exit; `stop_hook_active` exits; TaskCompleted continues to deny false completion. Claude's own continuation cap remains a backstop. |
| D02 | Deadlock | Blind QA/Chromium missing results in false success or endless retry. | **Mitigated**: deterministic failure, explicit pause; no silent screenshot fallback. This host blocks Chromium loopback navigation, so live E2E cannot be certified here. |
| U01 | Tooling gap | No actual ephemeral DB server, UI driver or visual oracle. | **Mitigated**: seeded unique disposable SQLite fixture, loopback HTTP demo, Playwright DOM scenarios, mockup PNG capture, pixel-diff threshold, evidence screenshots, black-box browser CLI. Integration into an arbitrary real app still requires user-defined safe fixtures. |
| U02 | Tooling gap | Browser comparison can leak network requests or visit wrong origin. | **Partly mitigated**: exact loopback URL/origin checks, Playwright request interception and bundled seeded server-only fixture launcher; a real firewall/container remains necessary against browser and process escapes. |
| U03 | Tooling gap | No PR CI or real deployment controls. | **Partly mitigated**: GitHub Actions test workflow; no automatic push, PR creation, merge queue, feature flag, alerts or rollback because those require target-repo integrations and operator policy. |
| U04 | Tooling gap | Demo signup form read `form.name.value`, a built-in form property collision; invalid/valid submission crashed. | **Fixed**: explicit `#name` and `#email` selectors, re-generated mockups, executable static-browser regression test. |
| U05 | Tooling gap | Blind browser lost form fields on each separate process invocation. | **Fixed**: persist bounded form field values in isolated browser session, restore after navigation, capture evidence after each action. Only use synthetic test identities. |
| U06 | Security | Script returns success after high-risk review while no human authorized final SHA. | **Mitigated**: release-attest requires independent interactive signatures bound to feature, current commit and eval digest; `complete` checks tiered count. |

## Red-team coverage included in repository

`tests/test_security.py` probes source reads, Git disclosure, shell pipes/substitution, Python command execution, unknown tools, stop recursion, noninteractive approval assumptions, stale eval scenarios and invalid path traversal. `tests/test_demo.py` tests SQLite isolation, HTTP validation, duplicates and forbidden server routes. `tests/test_ui_static.py` exercises client-side invalid form behavior with headless Chromium without claiming live E2E coverage.

## Residual P0 release blockers for a real production target

1. Install and validate actual Claude Code CLI version and effective hooks. This sandbox does not have Claude Code installed.
2. Run Playwright live loopback browser scenarios in an environment without administrative URL restrictions. Static render and API tests do **not** prove E2E signup; here loopback navigation fails `ERR_BLOCKED_BY_ADMINISTRATOR`.
3. Integrate real application's ephemeral DB migrations, fixtures, secrets isolation, API route configuration, and approved UI baselines; the included SQLite service is a demo.
4. Enforce immutable controller/approval policy and two-person high-risk review in protected remote CI/branch rules. A same-user local key is not a trusted separation of duties.
5. Configure deployment feature flags, gradual rollout telemetry, monitoring, and tested rollback for the actual application. This template does not deploy or merge on the user's behalf.

**Release conclusion:** v2 is a usable, validated reference package and local workflow scaffold. It is **not certified production-ready for an unknown application** until the five external gates above pass. There is no truthful way to fix missing environment access or OS isolation solely with repository files.
